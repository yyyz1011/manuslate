# Markdown 产品基线与原创取舍

调研日期：2026-09-12。

本项目不复刻任何竞品的代码、图标、布局或文案。调研只回答三件事：用户已形成什么预期、现有产品在哪些地方割裂、PatchMark 应该用什么原创交互补上。

平台范围：面向 macOS 与 Windows 的 PC 桌面工具。下文提到 Apple 平台，只指交互完成度与系统感，不代表移动端适配目标。

## 能力矩阵

| 产品 | 已验证的强项 | 用户仍需承担的代价 | PatchMark 的取舍 |
| --- | --- | --- | --- |
| Typora | 无分离预览窗口的实时排版；文件树、搜索、大纲；表格、数学、Mermaid、脚注 | 单文件体验强，但资料库治理、版本与跨文档关系不是中心 | 把实时排版做成默认，同时保留源码与阅读，避免锁死在单一编辑范式 |
| Obsidian | 本地 Markdown、实时预览/源码双模式、双链、属性、插件生态 | 能力依赖设置和插件，首次使用容易进入“搭系统”而不是写作 | 核心能力开箱即用；跨文档能力以后进入检查器，不污染正文 |
| Bear | Apple 平台原生感；隐藏标记；标签、目录、反向链接；移动端格式键盘 | 平台限制明显，强能力与同步多绑定订阅 | 借鉴系统交互纪律，用开放格式和本地文件保持可迁移 |
| Ulysses | 资料库、分组/筛选、写作目标、版本、导出与发布链路成熟 | 使用专有资料库心智，纯 Markdown 兼容能力需要取共同子集 | 未来吸收写作目标与版本恢复，但文件仍以 Markdown 为真源 |
| iA Writer | 专注模式、句子/段落聚焦、语法高亮、样式检查、自动保存 | 有意减少功能，组织和专业发布能力较弱 | 保留专注纪律，把统计、结构和高级插入放到上下文层 |
| MarkEdit | 免费开源、隐私、原生、轻量、大文件、多光标、严格 GFM | 预览与导出被视为外部扩展，面向完整写作流程时能力偏少 | 坚持轻量和标准兼容，但把阅读、导出作为核心能力 |
| MarkText | 开源跨平台、所见即所得、GFM、数学与 Mermaid | Electron 与块编辑内核较重；长期维护复杂 | 当前用 CodeMirror 渐进式实时排版，不引入私有块格式 |
| Zettlr | 引用、Pandoc 导出、项目、全文搜索、长文与学术工作流 | 功能密度高，界面与设置成本高于日常写作所需 | 学术与发布能力以后模块化接入，不让首屏变成工作台 |

## 市面空位

成熟产品通常在两条路线中二选一：

1. 极简但能力边界窄，遇到表格、长文档、发布与资料管理就要换工具。
2. 能力很强，但用户必须接受仓库、插件、数据库或密集工作台。

PatchMark 的机会不是“功能总数最多”，而是让复杂能力服从一条连续主路径：打开文件 → 直接在成稿上写 → 需要时看源码/结构 → 明确地写回文件或导出。正文是永久主界面，资料库和检查器是可收起的系统层。

## 当前已经落地

- 默认实时排版：离开光标所在行后隐藏主要 Markdown 标记。
- 实时排版、源码、阅读、对照四种视图，均可键盘切换。
- macOS 文档窗口式资料库、最近文稿摘要、全文搜索与可收起检查器。
- 段落专注、命令面板、上下文格式工具坞与高级插入菜单。
- GFM、任务列表、脚注、数学公式、代码块、表格与安全链接。
- 浏览器恢复草稿与本地文件写入分离，状态不混淆。
- Markdown、富文本、HTML 与系统打印/PDF 输出路径。

## 下一阶段优先级

| 优先级 | 能力 | 验收标准 |
| --- | --- | --- |
| P0 | 桌面壳与文件夹工作区 | 原生打开/保存/最近文件；文件句柄可跨会话恢复；无浏览器权限歧义 |
| P0 | 版本与恢复 | 每篇文稿可查看时间线、比较和恢复；不改写原文件直到确认 |
| P1 | 图片资产 | 粘贴/拖入图片自动放到可配置相对目录，链接始终可迁移 |
| P1 | 表格与 Mermaid | 表格可视化编辑；Mermaid 仅按需加载并提供错误定位 |
| P1 | 跨文档关系 | 双链、孤立文稿、重复主题在检查器内出现，不做强迫式知识图谱 |
| P2 | 发布管线 | 可复用导出样式；Pandoc 作为可选外部能力，不捆绑核心 |
| P2 | 本地扩展 API | 有明确权限、性能预算和可禁用边界，避免无限插件污染体验 |
